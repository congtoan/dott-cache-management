## 🔴 Lỗi đang ảnh hưởng

### [ ] F1. `cron-cache-segment-update-v2.py` bị treo vĩnh viễn
- Trên VPS có 3 tiến trình treo từ 20 đến 35 ngày (PID 4482, 44223, 53896), mỗi tiến trình kẹt một kết nối ESTAB tới Cloudflare.
- **Nguyên nhân:** `requests.get(archive_link, headers=...)` không có `timeout=`. Nhánh `except` cũng gọi lại `requests.get` không timeout.
- **Sửa:** thêm `timeout=30` vào mọi `requests.get`. Dùng `flock -n` trong crontab để không chạy chồng. Kill 3 PID cũ.
- **Hướng tốt hơn:** viết lại bằng `utils.trigger_cache`, gọi origin `127.0.0.1` thay vì đi qua Cloudflare.

### [ ] F2. Cron cũ không upload cache lên S3
- `cron-cache-clean-v2.py` và `cron-cache-segment-update-v2.py` chỉ xóa và tạo lại cache trên **disk**, không gọi `upload_files_to_s3`.
- **Cần xác nhận:** Cloudflare Worker phục vụ từ S3 hay từ origin? Nếu từ S3 thì các trang trong `url_list/clean_*.txt` và tag/archive của segment trên S3 sẽ cũ hơn bản trên disk (S3 chỉ được cập nhật khi đến lượt cache_renew, khoảng 3 tháng một lần).
- **Sửa:** chuyển 2 cron này sang dùng `utils` (trigger + upload), hoặc thay bằng `cache-urls-update.py` chạy theo cron với danh sách URL.

## 🟠 Dữ liệu

### [ ] F3. 3.865 URL có `lang`/`page_type` NULL
- Do `u2_update_db_and_kv_v3.3.py` chỉ `INSERT (url, cached)`. Các tool chạy với `--lang`/`--page_type` sẽ bỏ qua những URL này.
- **Sửa code u2:** INSERT đủ `lang` (theo prefix `/en/`), `page_type` (theo JSON nguồn single/archive), `page_number` (`utils.compute_page_number`).
- **Sửa dữ liệu** (kiểm tra mẫu trước khi chạy, trên DB VPS):
  ```sql
  SELECT url FROM urls WHERE lang IS NULL LIMIT 20;
  UPDATE urls SET lang = CASE WHEN url LIKE 'https://diaocthongthai.com/en/%' THEN 'en' ELSE 'vi' END WHERE lang IS NULL;
  ```
  `page_type` không suy ra chắc chắn từ URL được (archive trang 1 không có `/page/`), nên tốt nhất là đối chiếu với JSON từ A1.

### [ ] F4. Định dạng key KV không thống nhất
